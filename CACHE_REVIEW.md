# Cirrus caching and dependency-tracking review

Status: **Phase 1, read only.** Every finding below comes from reading; none has been probed. Phase 2 (`CACHE_CAMPAIGN.md`, to be written) will confirm, refute or downgrade each, as the scheduler review did. Scope and method are in [CACHE_LAYER_PLAN.md](CACHE_LAYER_PLAN.md); the detailed reader notes with the full file:line evidence are in `review-notes/` (`ring1-2.md` cache and key, `ring3.md` context, `ring4a-tracker.md` tracker and queue, `ring4b-ttracks.md` TTrack graph and cleanup, `xsft.md` cross-scenario reuse). Severity key as before: **H** likely to bite in production, **M** real but needs specific conditions, **L** hygiene or latent. Ids are per lens: D data loss and wrong results, R races and deadlocks, F foot-guns, P performance, W properties that hold.

## Executive summary (provisional)

The layer is three designs stacked on one invariant. The cache is a CAS-only, no-remove hash table with a ledger-batched LRU, sound on its hot path and honest about its at-least-once semantics. The key is a scenario stack whose `SSCacheID` is shared structurally between stacks that agree on tweaks, so memo sharing across `given` blocks is free. Invalidation is a lock-free CAS-append dependency graph (TTracks) that is read and rewritten by plain stores, which is only sound because the dependency-tracker queue guarantees that **no node writes to a tracker's graph while that tracker or an ancestor runs an update**. Most of what we found is either a hole in that invariant, a path that mutates a published node's scenario stack, or a queue that can wedge.

## D: data loss and wrong results

- **D1 (H)** `DelayedXSProxyNode.cancelInsteadOfRun` (cache/NCProxies.java:260–265) does `srcNodeTemplate().replace(scenarioStack().withRecorded(RecordedTweakables.empty()))` to "clean up some memory", assuming the key was never published. But `nextPossibleHit` publishes the key itself as owner when nothing matches, the proxy uses the default re-enqueue-on-child-completion, and `OGSchedulerContext.run:853` sends any re-run under a cancelled scope to `cancelInsteadOfRun`. Sequence: owner published, owner completes with its true recording frozen by `onOwnerCompleted`, the proxy's scope is cancelled, the proxy re-runs, the owner's recording is replaced by "none". `XSOwnerPolicy.matchesScenario` then accepts the owner for any request under the same root (`isDirectlyReusable` ignores scope for a usable result; `matchXscenario` against an empty recording trivially succeeds). Fix: scrub only an unpublished key, or nothing once `run` has been entered. Do not break: frozen-at-completion recordings.
- **D2 (M→H)** `DependencyTrackerRoot.traversalId`/`resetId` (tracking/DependencyTrackerRoot.scala:100–147): plain vars, every `TweakableTracker` in the tree uses the root as id source, concurrent child queues run updates concurrently. `MarkingGraphTraverser.shouldVisit` treats `lastUpdateTraversalID == calleeId` as visited. Shared tracks (by-name tweaks reaching into descendants' graphs, R4's tracks) are then partially skipped by the second traversal. `resetAllTraversalIds` also rewrites ids on graphs a sibling is traversing. Fix: `AtomicInteger` with `getAndAdd` reservations, or per-queue ids.
- **D3 (M)** `TPDMask.fromArray` (core/TPDMask.java:44) `Arrays.copyOf(maskArray, maskQWords)` drops high words; `stringDecoded` (used by `NodeCacheConfigs.scala:584` for optconf `dependsOnMask`) goes through it. `indexListToMask` and `fromIndex` fold modulo width, which only adds false positives. A PGO file generated under per-node masks (6 qwords) consumed by a default process (2) silently under-approximates `dependsOnTweakMask`.
- **D4 (M)** `ScenarioStackShared.setScenarioStack` (graph/ScenarioStackShared.scala:153) builds `siStack` as `ss.copy(flags = ALL_SI_FLAGS | …)`, same `_cacheID`. `getTweakResolver` (platform/ScenarioStack.scala:1050) throws `IllegalScenarioDependenceException` (an `RTExceptionTrait`, hence `isDoneWithUsableResult`) for a never-tweaked tweakable read under an SI ancestor. The failing node is cacheable with the root's id; the later root lookup is a hit. Needs a non-SI node reached from an SI node, which is exactly the situation the exception exists to report.
- **D5 (M)** graph/TweakExpander.scala:69–76 with `tweakTranslatorsMustBePure = false` (default): `replace` + `invalidateCache` on the running expander, then re-expansion. A concurrent sync waiter on the same cached expander exits `while (!ntsk.isDoneEx())` and reads an incomplete node. First production path for the scheduler review's R6.
- **D6 (M)** TTrack graph: evaluation appends with CAS; invalidation (`Invalidators`) and cleanup (`CleanupVisitor`) rewrite with plain stores. If a node merges or completes onto a track between `invalidateByKey` removing `root_k` and the next root being created, `nodeCompleted` prepends to an `Invalid` track and the node stays cached. Nothing detects it. Holes in the barrier found so far: R4 (invalidate outside the queue), `scenarioState`/`nc_scenarioStack` exposure (A12), async-suspended orphans resuming during an update (4b S8), D5. Cheap defence in depth: in `nodeCompleted`, if `initial == Invalid`, `invalidateCache` the node (or assert under `schedulerAsserts`).
- **D7 (M)** XSFT `ips` protocol: a reset proxy P (via `offerValue(null)` from recovery or `breakProxyChains`) stays on `U_old.promisedToDown`; after P re-runs with a widened snapshot, `U_old`'s late down-offer passes `canUseValue`'s identity fast path (compares P's *new* snapshot to the current mask) and P takes a value from above the tweak it was widened to avoid; the up-offer to `U1` then passes the slow path, which returns true when the walk never meets `to`. Deterministic to probe via the public `tryToRecoverFromCycle`.
- **D8 (M)** `tweakUsageQWords=0`: node-side subset/intersect stubs return true, the property mask never changes, so the fast path is always true and `minimumScenario` walks to the barrier. `NCPolicy.forInfo` does not downgrade. Fix: return `Basic` when `!enablePerNodeTPDMask`.
- **D9 (M, latent)** `NCPolicy.localMatch` (cache/NCPolicy.java:256) and `EntityImpl._localCache` (platform/storable/EntityImpl.java:70). No `propertyInfo` comparison, no `isInvalidCache`, single slot ignoring `localCacheSlot`, overwritten by `putIfAbsent:49` with proxies included. Exposure: zero in this export (no `LOCAL_CACHE` setter), M if the plugin or config sets bit 19.
- **D10 (M, conditional)** Non-monotone `dependsOnTweakMask` writes from optconf (`setDependsOnMask`, NodeTaskInfo.java:668) after values are cached defeat the "mask only grows" premise of the XSFT fast path. Depends on whether config can be re-applied to live infos (hot-swap is parked).
- **D11 (L)** Cleanup's `Nil`-middle-man bypass and `Invalid`-edge drop orphan tracks that a *held* completed node can still feed; needs a node object re-consumed across a cleanup. (4b S5)
- **D12 (M, demonstrated on AArch64)** `PtracksArray` resize: thread A CASes the last slot then plain-writes `nextFree`; B reads `nextFree` plainly and copies; no happens-before orders A's slot store before B's copy on weak memory models. W11 (jcstress, this Apple-silicon Mac, `-m default`): 5 forbidden outcomes in 4.0 G samples over three runs, always `nextFree = 9` with a null slot below it and one caller lost, with either actor as the loser, under mixed C2/C1/interpreter configurations. A lost caller is a lost invalidation for that node. Rare (about one per 800 M contended resizes) but real; a volatile `nextFree` or a `getVolatile` re-read of the copied tail fixes it. (4b S9; W11)
- **D13 (L→M, demonstrated)** `Scenario.equals` is asymmetric across ordered/unordered and the hash codes differ, so ordered and unordered scenarios never share a cache id (W5: ids 5 vs 6). But two *unordered* scenarios with the same duplicate-target tweaks in different orders do share one (`unordered(t1,t2)` equals `unordered(t2,t1)`, same hash), and resolution within a scenario is last-one-wins, so the second stack resolves the key to whichever tweak the first stack's cache id installed: `(t2,t1)` resolves k to 2 where its own order says 1. Reachable only through `resolveDupsByTakingLast` (plain `unordered` throws on duplicates). (ring1-2 S7, ring3; W5)
- **D14 (L, latent, demonstrated)** `optimus.graph.cache.Interner` spins forever in `Holder.internedValueOr` (`compareAndSet(null, …)` against a never-null reference). The path I predicted (hash lookup after the referent is collected) does not spin: the stale `HashLookup` no longer equals the new one and a fresh holder is built. The identity path does: intern `w`, then `intern(o)` for an equal but distinct `o` (its identity entry maps to `w`'s holder), drop `w`, let it be collected; `intern(o)` now spins with the cleaner running, since the cleaner removes `w`'s entries but not `o`'s. Unused in this export, so still L. (ring1-2 S8; W12)
- **D19 (M, new, H1-B)** Under `cacheConcurrency > 1`, an entry whose `putIfAbsent` has already returned can survive a later `clear()`. A concurrent hitter's `touchEntry` sets `entry.inLedger = true` before appending to its own ledger (NodeCacheWithLRU.java:222–225); the inserter's `touchEntry` then sees `inLedger` and records nothing; `clear()`'s `catchupCore` peeks `l.count == 0` without the ledger lock and skips the hitter's ledger, so the entry is in neither the LRU nor any processed ledger, and `getIfPresent` after the clear returns the old node. Found by Lincheck from random scenarios (seeds 3 and 4; trace in `probes/cache/modelcheck/results/lincheck-lax-3.txt`); the targeted jcstress pair (f) could not hit the window. For a cache whose `clear` is used to drop stale state (memory pressure, test resets, DAL config changes) this is a stale value, not just retention. Fix: inserters always record new entries regardless of `inLedger`, or `catchupCore` takes each ledger's lock before peeking.
- **D15 (M, new, W14)** `CleanupVisitor` makes a live node unreachable when an `Invalid` track has a non-`Invalid` caller. Minimal graph: root 0 → 1, 0 → 2, 1 → 2, track 1 `Invalid`, track 2 live. Cleanup drops the direct 0 → 2 edge as redundant (reachable via 1), then drops 0 → 1 because 1 is `Invalid`; node 2 is unreachable and root 0 is removed from the map. Exhaustive enumeration: 0 violations in 108 M instances over 21,479 graphs where every caller of an `Invalid` track is `Invalid` (the redundant-edge id algorithm itself held in every case), 524 k violations in 8.2 M instances once that precondition is broken. The precondition is a caller attached after invalidation, i.e. the D6 barrier hole, so D15 is the cleanup-time amplifier of D6: a node that was reachable directly becomes a silent stale hit. Fix: treat edges through an `Invalid` track as non-existent when deciding redundancy, or drop the redundant-edge pass for callers of `Invalid` tracks.

- **D17 (H, new, fuzzer N2, reproduced deterministically)** A cancelled requester poisons a cached by-name `TweakNode`, and every later requester in the scenario, cancelled or not, receives its `OptimusCancellationException`. Minimal shape: `S1 = given(a := byName(…))`, `S2` a child of `S1`, `X` a child cancel scope on `S2`; a requester in `S2.withChildCancellationScope()` cancels `X` and looks up `a`; afterwards `a` throws in both `S1` and `S2`. Mechanism: `withChildCancellationScope` copies only `siParams` (platform/ScenarioStack.scala:843–874), so the parents keep `NullCancellationScope`; `TwkResolver` finds the tweak in `S1` and calls `createNode(startSS = S2X, givenSS = S1)` (graph/TwkResolver.scala:128); the `TweakNode`'s own stack is `givenSS` (null scope) but its `computeSS` takes `siParams` from the requester, i.e. scope `X` (graph/TweakNode.scala:176–180, ScenarioStack.scala:961–966), and it is cached under `S1`; `run` enqueues the RHS under `X`, which is cancelled, so `cancelInsteadOfRun` completes it with the raw exception and `completeFromNode` copies that into the null-scope `TweakNode`; every null-scope requester then takes the fast path in `isUsableWRTCancelScopeAndEnv` (equal packed ids, NCSupport.java:202), which never looks at the hide bit. `BYNAME` and `BIND_ONCE` leak, `BIND` does not; a mid-flight variant (cancel while the RHS is blocked, with an uncancelled waiter on `S1`) also leaks 10/10. `probes/cache/run-repro.sh d17 10`: 10/10. Fix direction: run the RHS under the `TweakNode`'s own scope, or refuse to complete the `TweakNode` from a child that failed with a foreign scope's cancellation.
- **D18 (H, new, fuzzer N3, reproduced deterministically, single-threaded)** A `when`-predicated by-name tweak that turns false keeps serving its old value, because the cached `TweakNode` matches the *untweaked* key. Minimal shape: root tracker `t0` with `w := 8`; consistent child `t1` with `x := byName(…) when bit3(w)`; evaluate `x` in `t1` (57), set `w := 0` in `t0`, evaluate `x` again: still 57, expected 100 (a fresh sibling tracker gives 100). Mechanism: the `when` clause's dependency on `w` is attached to the resolver and the requester, not to the `TweakNode` (TwkResolver.scala:76–89, 250), and the `TweakNode` is cached under `t1`'s cache id (:128–132); the update invalidates `x`'s requesters but not the `TweakNode`; on the next lookup the `when` clause re-runs, says "no tweak", and `getNode` looks up the untweaked key (:116–117 → `completeGetNode`); `equalsForCaching` succeeds because a `ProxyPropertyNode` reports its template's `propertyInfo` and `args` (ProxyPropertyNode.scala:38–46, deliberate for delayed proxies and inherited by `TweakNode`), `matchesScenario` succeeds on the shared cache id, and the stale `TweakNode` (or a `DelayedCSProxyNode` over it, which is what the fuzzer served) is returned. Only the true-to-false direction is affected; a constant RHS is not cached and does not reproduce. `BYNAME`, `BIND_ONCE` and `BIND` all fail. `probes/cache/run-repro.sh d18 10`: 10/10, with and without a concurrent requester. ## W: properties that hold (candidates, with why, and what not to break)

- **W1 (upheld)** Cache insert is lock-free and never loses a concurrent insert of a different key: head CAS plus rescan of only the new segment. Same-key races are resolved by the loser finding the winner. W3 (jcstress): same-key inserts never left two live nodes and the lookup always returned the winner (109 M samples); same-bucket inserts never lost one (193 M); put vs clear never desynchronised LRU and table (118 M). Lincheck with the documented relaxations (resize window, lazy clear, ledger lag, partial sweep) passed 354 k executions with never two live nodes for a key and never a miss on a live key outside the resize window.
- **W2** At-least-once semantics are explicit and sound: every path that can miss (resize, concurrent unlink) is documented as "ok to execute twice", and `tryRun` plus RT values make that safe. Cost is duplicate computation only.
- **W3** Usability is one three-valued predicate (`isUsableWRTCancelScopeAndEnv`), with "not yet" turned into a proxy rather than a block or a miss.
- **W4** Packed ids are checked: 40 bits for cancel scopes, 24 for environments, panic on overflow. The opposite of the scheduler's R1.
- **W5** Mask compression folds in the index paths (false positives only); `dependsOnTweakMask` widens monotonically with a fresh instance per update under one monitor and a volatile read, so the XSFT fast path's identity test cannot suffer ABA. Do not break: never `merge` into a returned mask in place.
- **W6** XSFT under-approximation is self-correcting in the monotone flow: the property mask widens before the value's DONE is visible, so `value._tpd ⊆ mask` for anything `canUseValue` sees, and a stale optconf mask costs retries, not correctness. The evaluator always computes in its own lowest scenario, so trust is transitive on value-intrinsic masks.
- **W7** XS recordings are frozen before DONE (`onOwnerCompleted` precedes the state CAS) and the final match is redone on completion; partial matches on running owners are only a filter. (D1 is the one path that mutates a frozen recording.)
- **W8** The XSFT proxy never nests proxy monitors and makes no call-outs under its monitor apart from trace observers.
- **W9** Scenario stacks are immutable case-class copies with structural sharing; `_stableSS` is the only mutable pointer and is double-checked under `this.synchronized` with a volatile read. Cache-id interning does one `compute` per key, and initialisation after `compute` is under a lock so a racing thread waits for complete maps; "was tweaked" flags are published before the volatile init flag.
- **W10** Per-queue reader/writer exclusion with a cancel-scope epoch: an update starts only when nothing is in flight, no evaluation starts during an update, each phase gets a fresh child scope, and the barrier waits for nodes on a stack while suspended orphans are cancelled when they try to run. No user code runs under `queueLock`. FIFO with evaluation batching means an update never overtakes earlier evaluations and is never starved by later ones on its queue. Dispose runs on the root queue. Do not break: every evaluation entry point must take its cancel scope from the queue; that is the invariant the whole invalidation design rests on.
- **W11** Single-writer graph maintenance given the barrier: lock-free CAS append on the hot path, plain-store rewrite in updates. Do not fix D6 by adding locks to `addCaller`/`nodeCompleted`; fix the barrier holes and add the sentinel check.
- **W12** A node is in its TTrack before it is observably done; invalidated nodes are sticky-invalid in the cache (one predicate in `NCEntry`); untracked tweaks degrade to clear-all, not silence; the dependency graph holds nodes weakly; overlays cannot cross concurrent subtrees; the `UTrack` swap protocol is properly locked.
- **W13** Ledger batching keeps the LRU lock off the hot path (one `synchronized(ledger)` per hit, `tryLock` first); the hash is stored on the node and compared before `equalsForCaching`.

## Plugin contract (what hand-written nodes must satisfy)

From the cache: a singleton `NodeTaskInfo` (policies, masks and tweak ids hang off its identity); `argsEquals`/`argsHash` consistent with `entity.equalsForCachingInternal`; a key never reused after attachment; `isTrackingValue` if directly tweakable; a stable `entity`; no reads of plugin tags, node inputs or the environment except through the marking accessors. From the context: `TWEAKABLE` on the info or tweaks are ignored; `argsCopy` overridden for any node with arguments that may be tweaked by key or with `when`; tweak equality uses entity `==`. From the tracker: cacheable nodes must fetch tweakables through `getNode`/`lookupAndGet` in the tracker's stack so the listener callbacks fire; the info must not carry `DONT_TRACK_FOR_INVALIDATION`. Only the first group has assert-mode checks.
