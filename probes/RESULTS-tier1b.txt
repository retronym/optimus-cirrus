Key observations
- T3 (R3) QUANTIFIED. No exception, panic or hang in 15,791 stalled findWork passes over _evalAsyncTrackedNodes against 15.8 M concurrent enqueueAndTrackCompletion adds (8 non-graph threads) and 7.4 M removals from non-graph completer threads. foreach cannot throw (it breaks on the first null). It does skip: long-lived "sentinel" tracked nodes that were in the list for the whole pass (added before the pass entered, not yet completed after it, and still in the array after the pass) were not visited in 8,370 of 494,892 checks (1.7%) without delay, 28% with a 0-50 us park per element inside foreach (-Dprobes.delay.maxNanos=50000), 0.2% at ideal=2. One double visit in 6.5 M. So cycle detection on tracked nodes is silently incomplete on a stall pass; it is only made up for by the next stall.
- T4 (R4) DEMONSTRATED, permanent JVM-level deadlock on the first cross-scheduler recovery, even with no injected delay. Two OGSchedulers, keepTaskSchedulerAffinity=true, a two-node waitingOn cycle on each, a NodeTask whose tryToRecoverFromCycle enqueues a Leaf onto the other scheduler and returns true. findDeadlockedThreads reports both clients: one in OGScheduler.enqueue (BLOCKED on the other scheduler's OGSLock) <- tryToRecoverFromCycle <- detectCyclesAndRecover <- findWorkOnForwardChain:1293 holding its own OGSLock and NodeTask._visitLock; the other in detectCyclesAndRecover:1944 waiting for _visitLock while holding its own OGSLock. Control (only one scheduler has a cycle): 50 rounds, 2,000 cross enqueues, no deadlock.
- T5 (R5) QUANTIFIED. waitForCancelledNodesToStop returns as soon as the node stops in every configuration (no hoisting, also with -XX:-UseOnStackReplacement -Xcomp; Thread.yield keeps the loop honest). It burns the waiting thread for the duration: busy node, 2.0 s wait, 1.0-1.6 s CPU (mostly sys: yield); cancelled node sync-waiting a 100,000-long forward chain, 1.96 s wait, 1.89-1.99 s CPU (user), each poll iteration's visitForwardChain().containsEQ costs 3.0-4.6 ms.
- T6 (R6) DEMONSTRATED (mechanism end to end; no functional disturbance). Without a nudge, invalidateCache on the node T sync-waits does NOT release T: it stays parked (3 s observed) until A completes, so the frame is never reused stale. With any global enqueue after the invalidate (the waiter scan hands the task to T), T exits runAndWait in 6-7 ms with its SyncFrame still on A's waiter list; the next sync wait reuses the same SyncFrame object (frames[1], ntsk=RB, waitingOn=B); A's later completion runs notifyWaiters on it and clears its waitingOn (B -> null) while T is still waiting on B. T is not woken (awakeOnComplete compares awaitedTask), B's wait returns 0-1 ms after B completes, no GraphInInvalidState with asserts on. frame.waitingOn is not read by the scheduler, so the clobber is invisible today.
- T9 (F3) DEMONSTRATED. 10,000 calls -> 10,001 og.worker threads (ideal 18 or 2), all simultaneously alive, no OOM at -Xss512k -Xmx256m; after release the pool shrinks to idlePoolCount (36 resp. 4). At 15,000 calls the OS limit (kern.num_taskthreads 12288) is hit: OutOfMemoryError "unable to create native thread" thrown to the caller after 12,268 threads. New: the failed injectThread leaves its Context (thread=null, userEntry, awaitedTask = a node that never runs) in _workers forever. _workers.count never reaches 0, so (a) onGraphStalled callbacks never fire again (a client waiting on a node only a stall callback completes hangs; control fires), and (b) a spinner thread stays in _workers spinning at 0.76 CPU-s per second indefinitely.
- T10 (F4) NOT_REPRODUCED, W6b confirmed end to end. Nodes enqueued through asIfRunning carry causality 0/0 (never 1/x), both inside the supplier and after it returns; thread id 1 (the first injected worker of a fresh scheduler, at sync depth 4, awaitedCausality 2) runs the node and stamps it 1/2 itself. Making that node sync-wait L, which is lower on thread 1's sync stack, deadlocks permanently, and identically with an emulated asIfRunning using a fresh id 30001: the cause is that enqueue's waiter scan gives an unstamped (0/0) external node to a waiter at causality 2 (same delivery path as R9), not the id collision.
- T11 (I1) QUANTIFIED. Plain-loop benchmark, 20,000 iterations after 5,000 warm-up, completer hands off when the client sets parked. Median blocking sync get 3.1 us (cheap node, shallow) to 7.5 us (20-arg node at stack depth 205); toString 0.13 us cheap / 0.5 us for a 333-char 20-arg render, new Exception 0.29 us at depth 5 / 2.75-3.25 us at depth 205, so the two unconditional allocations are 13% of the fastest wait and 42-44% at depth 205; end to end the deep, expensive case costs +4.3 us per wait. With a 50 us handoff (client truly parks, median 62-66 us) the share is 1% shallow, 6% at depth 205.
- T12 (I2) QUANTIFIED (threshold not met). ideal=4, one 5 s busy node, nothing else runnable: the spinner og.worker-1-3 burned 4.17 s CPU (median 91% per 100 ms sample, 33/49 samples >= 80%) when a client thread runs the node, 3.31 s (median 68%, 0 samples >= 80%) when an og worker runs it. Most of a core for the node's duration, but below the ">= 80% for the duration" criterion.
