New finding (H2 e): NodeTask.markAsRunnable is check-then-act on _state.
  if (!isDoneOrRunnable()) updateState(0, STATE_NOT_RUNNABLE);   // NodeTask.java:762
updateState is an unconditional CAS loop, so a complete() that lands between the check and the CAS has its
STATE_NOT_RUNNABLE cleared: state 0x5 (STARTED|DONE_FLAG). isDone() is then false on a completed node,
isRunnable() true, and the caller (onChildCompleted -> markAsRunnable; eq.enqueue(this)) enqueues it; the
worker's tryRun succeeds, so run() executes again on a completed node and its second completion goes to
logAndDie (exit 121, or the F1b silent swallow). run.sh h2e replays that interleaving deterministically:
  markAsRunnable check passed before complete: true
  after race: state=0x5 isDone()=false isDoneEx()=true isRunnable()=true
  tryRun: prev NOT_RUNNABLE clear = true (scheduler would run the node again)
  after tryRun: state=0x7 isDone()=true (tryRun re-set NOT_RUNNABLE, so the re-run's completion is detected)
  second complete(): logAndDie entered = true; state=0x7 isDone()=true
Needs a node that completes while one of its own child subscriptions fires concurrently: a waiting node
completed by another thread (detectCyclesAndRecover completes a node in the middle of a wait chain;
cancellation / tryCompleteWithException from a non-graph thread) or markAsRunnableAndEnqueue racing a
completion ("helps plugins that enqueue nodes twice"). Fix: use tryUpdateState (as tryMarkAsRunnable does),
which the control test (e') shows is race-free.

Lincheck finding (strict trace below): growArray can move _base backwards by more than one. Thieves steal
T0, T1, T2 (base 0 -> 3) while the owner's growArray is copying; the swap writes _base = 1 and resurrects T1
and T2 in the new array, both of which are later handed out again (pop 3, steal 1, scan 2). W1d saw one
resurrected task; this shows several at once, so size() can overstate pending work by up to the number of
steals that overlap the copy. No loss in any configuration.

Testability findings:
- jcstress forks accept the entity agent through -jvmArgsPrepend without trouble.
- Lincheck 2.39 (dynamic ByteBuddy agent) cannot instrument the agent-rewritten NodeTask: "Unable to transform
  optimus/graph/NodeTask ... IllegalStateException: Internal error: can't find field with m2 in class
  optimus/core/TPDMask". The entity agent's TPDMaskTransfomer adds fields m2.. to TPDMask at load time, and
  Lincheck's FinalFields reads the untransformed class file. NodeTask therefore runs uninstrumented (no
  switch points inside it). This does not matter for the WorkQueue model (tasks are passive; every shared
  access is in OGSchedulerContext$WorkQueue, which is instrumented, as the traces show), but it rules out
  Lincheck for H2, which is why H2 is jcstress only.
- Lincheck's linearizability checker cannot express at-least-once delivery, so H1Lincheck uses a custom
  Verifier (AtLeastOnceVerifier): a DFS over linearizations consistent with Lincheck's happens-before clocks
  against a nondeterministic spec (push at top; pop top / steal bottom / scan topmost takeable with removeAt's
  bottom-into-slot move; any consumer may also return an already-delivered id; "none" only when the spec has
  nothing to take), plus a no-loss check of the final spec state against the real queue's live region read via
  @StateRepresentation. Duplicates are allowed at any time, which is weaker than "only while a concurrent
  consumer holds it"; tightening that is future work.
